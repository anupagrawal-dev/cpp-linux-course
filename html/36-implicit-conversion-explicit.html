Implicit Conversion & explicit

A single-arg constructor lets the compiler auto-convert; explicit turns that off.

Test yourself ↓

◆ Concept core idea▲ Watch out easy to get wrong

◆ Concept

Key concepts

  1. A single-argument constructor is a converting constructor: the compiler can use it to auto-convert that arg type into your class (Entity e = 22;).
  2. Implicit conversion also fires in function arguments and return values, not just assignments.
  3. Rule: at most one user-defined conversion in a chain — so Entity e = 22; works (one), but Entity e = "Anup"; fails (char* -> string -> Entity = two).
  4. explicit on a constructor disables implicit conversion through it; you must construct directly (Entity e(22);) or cast ((Entity)22).
  5. Why: implicit conversions can silently hide bugs. Guideline: mark single-arg constructors explicit unless you deliberately want the conversion.
  6. Direct init Entity e(22); always works; copy init Entity e = 22; is what explicit blocks. explicit also applies to conversion operators (C++11).

Easily confused

implicit vs explicit conversion
Implicit = compiler auto-converts via a single-arg ctor (Entity e = 22;). explicit = you must convert on purpose (Entity e(22); or a cast).
direct init vs copy init
Entity e(22); = direct (works even with explicit). Entity e = 22; = copy init (blocked by explicit).
one vs two user conversions
The compiler allows only ONE user-defined conversion. int->Entity = one (ok). char*->string->Entity = two (error).
